Introduction

Leftover Roulette

Transforme les ingrédients oubliés de ton frigo en plats réalistes — avec un moteur de matching qui te dit exactement quoi acheter pour compléter la recette.

73% Matching moyen
≤ 5 Ingrédients max
4 Écrans principaux
lightbulb
Le concept — Tu as 3 ingrédients random au frigo (demi-oignon, sauce soja, fromage frais). L'app te propose non pas une recette complexe, mais un plat réaliste à 5 ingrédients max, et surtout te dit : "Avec ces 3 ingrédients, tu as 73% des composants d'une Quiche Lorraine basique. Achète juste pâte à tarte et lardons."

Smart Matching — L'algorithme

Le cœur de l'app. Quand l'utilisateur saisit ses ingrédients, le moteur calcule un score de correspondance pour chaque recette Firestore et retourne les meilleurs résultats triés par pertinence.

Formule de calcul du score

score = (ingrédients_matchés / total_ingrédients_recette) × 100 
// lib/domain/use_cases/match_recipes_use_case.dart
class MatchRecipesUseCase {
  List<RecipeMatch> execute(
    List<String> userIngredients,
    List<Recipe>   recipes,
  ) {
    return recipes
      .map((recipe) {
        final matched = recipe.ingredients
          .where((i) => _fuzzyMatch(i.name, userIngredients))
          .toList();

        return RecipeMatch(
          recipe:              recipe,
          matchScore:          matched.length / recipe.ingredients.length,
          matchedIngredients:  matched,
          missingIngredients:  recipe.ingredients.where((i) => !matched.contains(i)).toList(),
        );
      })
      .where((m) => m.matchScore > 0.3)   // seuil minimum 30%
      .toList()
      ..sort((a, b) => b.matchScore.compareTo(a.matchScore));
  }

  bool _fuzzyMatch(String ingredient, List<String> userList) {
    final normalized = ingredient.toLowerCase().trim();
    return userList.any((u) => normalized.contains(u.toLowerCase()) ||
                                    u.toLowerCase().contains(normalized));
  }
}

Mécanique Roulette

Le bouton "Spin the Roulette" déclenche une animation simulant un tirage au sort, avant de révéler le meilleur match. Le résultat est déterministe mais l'UX crée un effet de suspense.

casino

Séquence d'animation

  1. Shake animation sur le bouton CTA (300ms)
  2. Écran "spinning" — ingrédients qui défilent en boucle (1.5s)
  3. Slow-down progressif et reveal du nom de la recette gagnante
  4. Navigation vers la page Résultat avec slide-up transition

Shopping List Generation

Les ingrédients manquants de la page Résultat peuvent être ajoutés à la liste de courses. La liste est persistée dans Firestore et synchronisée en temps réel sur tous les devices de l'utilisateur.

shopping_basket

Comportement

  1. Tap "Add to List" → item ajouté à /users/{uid}/shoppingLists/{listId}/items
  2. Checkbox cochée → champ checked: true mis à jour en temps réel via Firestore stream
  3. Badge sur l'icône Shopping (nombre d'items non cochés)
  4. Reset automatique de la liste après "Start Cooking Now"

Zero Waste Score

Score estimant le ratio d'ingrédients utilisés vs gaspillés. Affiché sur la Home et dans la page Résultat pour sensibiliser à l'impact alimentaire.

// Score simplifié — peut être enrichi avec un modèle ML
wasteScore = (ingrédients_utilisés / ingrédients_possédés) × 100

Screens

Les 4 écrans principaux de l'application, interactifs et navigables — prévisualisés dans un mockup iPhone.

Home — Spin Screen

L'écran principal. L'utilisateur saisit ses ingrédients disponibles et lance la roulette pour obtenir une suggestion de recette.

Résultat — Match Screen

Présente la recette correspondant le mieux aux ingrédients saisis, avec le score de matching et les ingrédients manquants.

  • Anneau SVG — Visualisation du % de correspondance avec icône eco
  • Cook time card — Card gradient orange avec durée estimée

Liste de courses générée automatiquement à partir des ingrédients manquants, persistée sur Firestore.

Cooking Steps — Mode cuisine

Instructions pas-à-pas adaptées aux ingrédients disponibles. Conçu pour être lisible à distance et mains sales.

Security Rules

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // Recettes — lecture publique, écriture admin seulement
    match /recipes/{recipeId} {
      allow read:  if true;
      allow write: if request.auth != null
                   && request.auth.token.admin == true;
    }

    // Données utilisateur — accès uniquement à son propre doc
    match /users/{userId} {
      allow read, write: if request.auth != null
                         && request.auth.uid == userId;

      // Listes de courses — sous-collection privée
      match /shoppingLists/{listId} {
        allow read, write: if request.auth != null
                           && request.auth.uid == userId;
      }
    }
  }
}

Offline support — Firestore est configuré en mode persistenceEnabled: true pour permettre la consultation et la modification de la liste de courses hors connexion, avec sync automatique au retour réseau.
